# 設計手法とルール（案）

> AIの提案。作者の確認後に確定版にして、`CLAUDE.md` に反映する。

## 1. 設計の進め方（上から順に。戻ってよい）

| 段階 | やること | 書く場所 | 書く人 |
|---|---|---|---|
| 0. 欲求 | 書きたいもの・やりたいことを出す | `構想メモ.md` | 本人 |
| 1. 芯 | コンセプト1行、テーマ（作中では言わせない）、敵（例：繰り返し・停滞） | `設計/決定ログ.md` | AIが本人の決定を記録 |
| 2. 人物 | 人物ごとに、欲しいもの（水一杯の小さい欲求／大きい欲求）、邪魔するもの、弱点、変化 | `設計/キャラ/` | AI案 → 本人が決める |
| 3. ビート | 部ごとに10場面前後。1行ずつ「誰が何を欲しがる／何が邪魔する／何が変わる」 | `設計/プロット/` | AI案 → 本人が決める |
| 4. 場面カード | ビート1つにつき1枚。上の3つに加えて「この場面に必要な設定」 | `設計/プロット/` | AIと本人 |
| 5. 本文 | 場面カードをもとに書く | `本文/` | **本人だけ** |
| 6. 振り返り | 書いた本文への講評。設計に戻す点を出す | `設計/講評/` | AI |

**設定（世界観）は、場面カードが必要としたときだけ作る。** 世界観を先に積み上げない。これがワールドビルダー病への対策です。使わない案は `倉庫` に置いておく。

## 2. ルール

### 本人の文とAIの文を分ける
- `構想メモ.md` と `本文/` には本人の文だけを置く。AIは書き換えない。ただし、本人がチャットに書いた文をそのまま貼るのはよい。
- `構想メモ.md` は追記だけにする。古い案も消さない（消すと考えた経緯がわからなくなるため）。
- AIの提案・講評・整理は、すべて `設計/` に書く。

### 決めるのは本人
- AIは「選択肢＋おすすめ」の形で出す。決まったことのようには書かない。
- 本人が決めたことは、AIが `設計/決定ログ.md` に日付つきで記録する。「何を決めたか」と「元になった本人の発言はどこにあるか」を書く。
- 設計どうしで食い違ったら、決定ログを正とする。

### 書く前の点検（どの提案にも当てる）
1. 主要な人物は、全員何かを欲しがっているか（水一杯でもいい）
2. トラブルから**助ける**のが偶然になっていないか（巻き込む偶然はよい）
3. テーマを台詞で言わせていないか
4. その設定は、どれかの場面に必要か（必要でなければ倉庫へ）
5. 「すごくやりたい」3つ（発掘・収集／見守りと成長／お互いになくてはならない）につながっているか

### 子セッションの使い方
- お題1つにつき、子セッションを1つとフォルダを1つにする。子セッションは自分のフォルダにだけ書く。
- 子セッションは、それぞれ自分のブランチに push する。マスター（このセッション）が取り込んで、食い違いを整理する。
- 子セッションの成果は「案」として扱う。決定ログに入るまでは確定ではない。

## 3. フォルダー構成（案）

```
小説/
  構想メモ.md          本人の構想（追記だけ）
  本文/                本人の原稿（第01話.md …）
  設計/                AIが書く
    00_設計手法とルール.md
    決定ログ.md        本人が決めたことの記録
    提案/              マスターでの提案（01_次の一手.md、02_太郎の切迫した事情.md …）
    キャラ/            人物（子セッション）
    世界観/            石・衝突・村など（子セッション）
    プロット/          ビート、場面カード
    講評/              本文への講評
    倉庫.md            今は使わない案の索引（旧案の軌道エレベーター・火星・AIなど）
```

いま動いている子セッションは、`設計/キャラ/` と `設計/世界観/` に書いています。この構成に合っているので、止めなくて大丈夫です。

## 4. 作者に決めてほしいこと

1. **構想メモは1つのファイルに追記していく？それとも日付ごとにファイルを分ける？**（例：`構想メモ/2026-11-17.md`）
   - おすすめ：日付ごとに分ける。長くなっても、どの時点の考えかが追いやすいため。
2. **決定ログは必要？** 本人の文を増やさずに「何が決まったか」を残すための仕組みです。
   - おすすめ：使う。
3. **AIの講評（本文への感想・指摘）はほしい？** ほしい場合、どのくらい厳しくする？
4. **設計の段階は、この6段階でいい？** 省きたい段階、足したい段階はある？
